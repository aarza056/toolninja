## What is ToolNinja?

ToolNinja is a free, browser-based developer toolbox. Every tool processes your input locally in
the browser — what you paste into a tool isn't sent to our servers. No accounts required. (A few
tools, like the HTTP Request Builder and the README Badge Generator's live stats, make requests to
the APIs *you* point them at — that's what those tools do.)

What does involve a server:

- **Ask Ninja (AI)** — questions you submit, and an image if you attach one, are sent to
  Anthropic's API to generate the answer. The paste detection that runs as you type stays in the
  browser; we keep only anonymous counts, a short topic label and, when no tool fits, a one-line
  summary of the tool you needed — never your question.
- **Ratings and comments** on tool pages are stored on our server (anonymously — no account, no IP
  address; spam checks use a daily-rotating hash).
- **Ads and analytics** — the site shows Google AdSense ads, uses cookieless Vercel Analytics, and
  loads Google Analytics only if you accept analytics cookies.

The [privacy policy](https://toolninja.io/privacy) has the details.

## ✨ Why ToolNinja?

- **Tools run in your browser** — your input stays on your machine
- **Zero setup** — open a tool and start working, no account

## 🚀 Run Locally

```bash
git clone https://github.com/aarza056/toolninja.git
cd toolninja
npm install
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). Without environment variables the tools work
as normal; Ask Ninja falls back to local detection and storage uses an in-memory fallback.

Optional `.env.local` settings:

| Variable | Used for |
|---|---|
| `ANTHROPIC_API_KEY` | Ask Ninja AI answers and comment moderation |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash Redis (set automatically by the Vercel integration) |
| `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` | `/admin` sign-in |
| `TELEGRAM_BOT_TOKEN` | Admin alerts |
| `VERCEL_API_TOKEN` (+ `VERCEL_TEAM_ID` for team projects, `VERCEL_ANALYTICS_PROJECT` if not `toolninja`) | Admin → Analytics and the Telegram `/visitors` commands |
| `NEXT_PUBLIC_GA_ID` | Google Analytics (consent-gated) |

Checks: `npm test`, `npx tsc --noEmit`, `npx next lint` — CI runs all three on every push and pull request.

## ➕ Adding a New Tool

1. Add an entry to `lib/tools.ts` (slug, name, description, icon, category, keywords).
2. Create `app/tools/<slug>/page.tsx` — server component with `generateToolMetadata("<slug>")`,
   `<ToolJsonLd slug="<slug>" />` and `<ToolSeoSection slug="<slug>" />` (copy an existing tool page).
3. Create `app/tools/<slug>/<Name>Client.tsx` (`"use client"` — the interactive tool). Put pure
   logic in `lib/<name>.ts` and add a test for it in `tests/`.
4. Add a hand-written title and description to `toolMeta` in `lib/metadata.ts`.
5. Add SEO content to `lib/tool-content.ts` (about, useCases, tips, faq).
6. Optional: add the slug to `LATEST_TOOL_SLUGS` in `lib/tools.ts` (NEW badges, What's New popup)
   and a release entry to `lib/changelog.ts`.
7. Run `npm run readme:tools` to refresh the tool list above.

The sitemap, `/tools`, the category hubs, `/llms.txt` and the search palette all read
`lib/tools.ts`, so they pick the new tool up automatically. `/admin` → Content health flags
anything missing.

## 📁 Project Structure

```
app/
  layout.tsx          → Root layout (sidebar, banner, Ask Ninja, analytics)
  page.tsx            → Homepage
  tools/<slug>/       → Individual tool pages
  ask/                → Ask Ninja page
  admin/              → Owner dashboard (password + 2FA)
  api/                → Ask Ninja, reviews, admin and Telegram endpoints
  blog/               → Blog articles
  sitemap.ts          → Sitemap, generated from the registries
  llms.txt/           → /llms.txt, generated from the tool registry

components/           → Shared UI (Sidebar, ToolLayout, CommandPalette, assistant/, admin/, reviews/)

lib/
  tools.ts            → Master tool registry
  tool-content.ts     → SEO content per tool
  metadata.ts         → Titles, descriptions, JSON-LD
  kv.ts               → Upstash Redis wrapper with an in-memory dev fallback

tests/                → Vitest unit tests for lib/
```
